POR QUÉ `mailto:` NO FUNCIONA EN EL PREVIEW DE REPLIT
───────────────────────────────────────────────────────
Replit embebe la app en un <iframe> con sandbox de seguridad.
Ese sandbox bloquea la navegación a protocolos externos por diseño.
Esto afecta:
  ✗ window.location.href = "mailto:..."
  ✗ window.open("mailto:...", "_blank")
  ✗ document.createElement("a").click()
  ✗ <a href="mailto:..."> al hacer click en el iframe

COMPORTAMIENTO EN PRODUCCIÓN (fuera del sandbox)
─────────────────────────────────────────────────
El link <a href="mailto:info.ixchelexperience@yahoo.com?subject=...&body=...">
funciona correctamente en:
  ✓ Chrome / Firefox / Safari en desktop
  ✓ Safari en iPhone → abre Mail.app
  ✓ Chrome en Android → muestra selector de apps de correo
  ✓ Outlook, Thunderbird, etc.

TEST VÁLIDO (cómo verificar en producción)
──────────────────────────────────────────
  Método 1: Deploy a Railway / Vercel y abrir la URL pública directamente.
  Método 2: Correr `pnpm --filter @workspace/riviera-cancun dev` y abrir
            http://localhost:21880 directamente (no a través del iframe de Replit).
  Método 3: Abrir la URL de Replit Dev (...spock.replit.dev/...) en una
            nueva pestaña fuera del iframe → el mailto funciona.

DISEÑO DEL EMAIL STEP
──────────────────────
El "Email Step" fue diseñado para funcionar en todos los contextos:
  - En browser real: botón "Abrir cliente de correo" abre directamente.
  - En iframe/sandbox: muestra el destinatario, asunto y mensaje copiables.
    El usuario puede copiar manualmente y enviar desde su cliente.
  - Sin JavaScript habilitado: igual se ven los datos.

SITUACIÓN ACTUAL
────────────────
El sistema usa el perfil personal de Facebook (rodrigo.fimiani).
Esto funciona, pero tiene limitaciones:
  - Los links m.me de perfiles personales pueden mostrar pantalla
    de verificación de Facebook para usuarios no logueados.
  - Facebook prioriza m.me para Páginas de negocio verificadas.
  - Un perfil personal no puede usar el widget de Messenger ni el
    Messenger Business API.

CUÁNDO HACER LA MIGRACIÓN
──────────────────────────
Crear una Página de Facebook del negocio (no perfil personal) cuando:
  a) el negocio tenga nombre registrado / marca definida
  b) se quiera habilitar Messenger Business API (chatbot, notificaciones)
  c) se quiera aparecer en búsquedas de Facebook como negocio

PASOS EXACTOS PARA MIGRAR (cuando esté listo)
──────────────────────────────────────────────

  PASO 1: Crear la Página en Facebook
    → facebook.com/pages/create
    → Categoría: "Agencia de viajes" o "Tour Operator"
    → Elegir username: ejemplo @australcancun o @australcancunpremium

  PASO 2: Activar Messenger en la Página
    → Configuración de la Página → Mensajería → activar

  PASO 3: Editar UNA sola línea en contact.ts

    Antes:
      messengerUrl: 'https://m.me/rodrigo.fimiani',
      facebookPageUrl: 'https://www.facebook.com/rodrigo.fimiani',

    Después (ejemplo):

6. RIESGOS RESIDUALES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  RIESGO 1 — Messenger en perfil personal (BAJO-MEDIO)
  ──────────────────────────────────────────────────────
  Los links m.me en perfiles personales pueden mostrar una pantalla
  de verificación de Facebook para usuarios no logueados. Esto NO es
  un bug del código — es comportamiento de Facebook.
  Mitigación actual: auto-copy del mensaje + fallback al perfil de Facebook.
  Solución definitiva: migrar a Página de negocio (ver sección 3).

  RIESGO 2 — WhatsApp número argentino para mercado mexicano (BAJO)
  ──────────────────────────────────────────────────────────────────
  El número actual es argentino (5491138475846). Si el público objetivo
  son turistas en México que prefieren un número local, puede generar
  dudas. Funciona igual de bien técnicamente.
  Mitigación: en el footer se muestra como "WhatsApp" sin el número visible.

  RIESGO 3 — Instagram null (BAJO)
  ──────────────────────────────────
  El ícono de Instagram está oculto mientras instagramUrl sea null.
  Si se crea la cuenta y no se actualiza contact.ts, el ícono seguirá oculto.
  Mitigación: es intencional. Mejor oculto que con un link roto.

  RIESGO 4 — Email a Yahoo en spam (BAJO)
  ─────────────────────────────────────────
  Los clientes de correo pueden marcar como spam mensajes con
  cuerpos largos generados automáticamente.
  Mitigación: el Email Step muestra el asunto y permite que el
  usuario lo envíe desde su propio cliente, que tiene reputación.

  RIESGO 5 — Contact.tsx formulario no conectado a API (PENDIENTE)
  ─────────────────────────────────────────────────────────────────
  El formulario de la sección "Contacto" hace console.log pero no llama
  a ningún endpoint. Los mensajes se pierden.
  Prioridad: ALTA para producción.
  Fix: conectar a POST /api/leads o a un proveedor de formularios (EmailJS,
  Formspree, SendGrid, etc.)
